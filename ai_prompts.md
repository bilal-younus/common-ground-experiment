## Implementation decisions and debugging notes

The assistant selected simulated agents for a keyless local demo, one server process, PostgreSQL snapshots committed before broadcast, explicit public-state allowlists, session tokens rather than IP identity, and the participant-facing explanation of all tie criteria. These are assistant-proposed implementation decisions, not claims that the candidate independently wrote every line.

During browser verification a React effect returned the result of scrollIntoView, causing an invalid cleanup callback in the browser. The effect was changed to return nothing; the app was rebuilt and checked again. The user then identified overly fast, isolated agent contributions; their feedback led to slower randomized pacing, a maximum of two contributions per discussion, and new-peer-message gating for follow-ups. Timing randomization never selects election winners.
